# 12주차 게임제작반 공통 실습 파일

## 목적
VS Code의 GitHub Copilot Agent로 **기존 게임에 클릭 횟수 조건과 선택 분기**를 추가하고, 수정 사항을 검증한 뒤 GitHub Pages로 배포한다.

## 파일 구조
- `index.html`: 게임 화면과 HTML 부모·자식 관계
- `css/style.css`: 게임 디자인 및 반응형 스타일
- `js/script.js`: 이미 작동하는 클릭 횟수 증가·초기화와 에이전트 작업 지점
- `images/signal.svg`: 버튼 영역의 시각적 아이콘

## 시작 상태
- `신호 보내기` 버튼을 누르면 클릭 횟수가 1씩 증가한다.
- 진행 표시가 최대 3/3까지 증가하며, `횟수 초기화`를 누르면 0으로 돌아간다.
- **3회에 도달해도 다음 상황이 열리지 않는다.** (의도적으로 남긴 실습 과제)
- 선택 A/B는 비활성화되어 있다.

## Copilot Agent 공통 실습 요청문

> 현재 프로젝트의 `.game-container` HTML 구조를 분석하고 다음 기능을 추가해 줘.
> - `.action-button` 클릭 횟수가 3회 이상이면 `.next-stage`의 '잠금' 안내를 '다음 상황이 열렸습니다'로 변경한다.
> - 그때 `.choice-a`, `.choice-b` 버튼을 활성화한다.
> - 선택 A를 누르면 `.choice-result`에 'A를 선택했습니다. 상황 A로 진행합니다.'를 표시한다.
> - 선택 B를 누르면 `.choice-result`에 'B를 선택했습니다. 상황 B로 진행합니다.'를 표시한다.
> - 클릭 횟수 증가 및 진행률 기능은 유지한다.
> - `.reset-button`을 누르면 클릭 횟수, 다음 상황의 잠금 상태, 선택 결과가 모두 초기화되어야 한다.
> - 기존 HTML과 CSS 디자인을 유지하고, 필요한 파일만 수정한다.
> - 변경 전 수정할 파일과 작업 계획부터 알려줘.

## 검증
1. 시작 시 클릭 횟수는 0이고 선택지는 비활성화되어 있다.
2. 1~2회 클릭에서는 잠금이 유지된다.
3. 3회 클릭 시 다음 상황이 열리고 A/B 버튼이 활성화된다.
4. A와 B를 각각 누르면 서로 다른 결과 문구가 나온다.
5. 초기화하면 클릭 횟수와 선택 상태가 처음으로 돌아간다.
6. GitHub Pages에서도 동일하게 작동한다.

## GitHub Pages 배포
1. VS Code에서 폴더를 열고 브라우저로 `index.html`을 실행한다.
2. GitHub 저장소를 만들어 이 폴더의 파일을 저장소 **루트**에 업로드한다.
3. 저장소 `Settings > Pages`에서 `Deploy from a branch`, `main`, `/(root)`를 선택한다.
4. 제공되는 Pages URL로 접속해 아이콘·스타일·버튼을 확인한다.
